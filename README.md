# 告警关联运行系统（alertcorr）

把同一故障引起的重复告警归并为一个事件，处理恢复与再次发生，并为一个告警
关联多条相互独立的原因解释。

## 设计要点

- **合并依据身份而非相似度**：只有 fingerprint（source+check）与轮次（epoch）都相同的
  firing 告警才并入已有事件；绝不按消息文本相似度合并。
- **恢复与再次发生**：恢复告警必须携带与活动事件相同的 epoch 才能关闭它；
  迟到恢复（旧 epoch）记为 stale_recovery，不会关闭新一轮事件；新一轮 firing 开新事件。
- **父故障抑制子告警需显式依赖证据**：子告警必须自带 depends_on 声明，且规则集的
  依赖图确认该边，才被活动父事件抑制；抑制关系持久化在 suppressions.json，重启后仍生效。
- **依赖图变更影响审查**：ApplyRules 应用新规则集时审查全部未结束的抑制——依赖边
  被撤回的抑制解除并通知，仍在图中的保持；每条抑制记录当初判断所用的规则版本。
- **父告警迟到**：子告警先于父告警到达时先开自己的事件；父事件开立后把带有效依赖
  证据的活动子事件吸收为被抑制状态。
- **分析人员临时解除**：LiftSuppression 暂时解除一条抑制并返回证据（父事件是否活动、
  依赖边当前是否确认、判定所用规则版本）；操作结束后 Reevaluate 按当前状态重新判断，
  证据仍成立则恢复抑制，否则正式解除。
- **通知只写本地记录**：通知持久化在 notifications.json，按去重键判重；
  同一 ID 的告警重复重放直接记为 duplicate，不产生多份通知、不改动事件。
- **生命周期主体身份统一**：同一子事件的抑制、原因撤回与恢复通知共用同一
  `subject_id`（子事件 ID），调用者可按同一主体串联整个生命周期；原告警标识
  与指纹作为 `alert_id`/`fingerprint` 关联信息随通知保存，可查询但不参与判重。
  再次发生开全新子事件，不复用旧事件的判重身份；两个独立父事件的同类通知
  仍按各自事件身份分别保留。
- **多原因关联**：同一个告警可同时挂多条独立原因，分三类可查看：
  `confirmed`（已确认：告警自带依赖证据且规则图确认）、`suspected`（待核实：
  规则图命中活动父事件但尚无显式证据）、`withdrawn`（被撤回：父恢复/边撤回/
  操作者移除，保留原因、规则版本与时间）。只有全部已确认原因都消失才恢复通知，
  单个父事件恢复不会重新通知；待核实原因绝不压掉独立告警的通知。
- **原因状态可查看且全程可追溯**：`ViewCauses` 返回已确认/待核实/被撤回三组
  解释及各自当前影响的告警；每条解释带 `history` 状态变迁与 `scope` 关联范围，
  原因后来补到（suspected→confirmed）、关联范围收窄、两个原因先后恢复都可追溯。
- **预演移除原因**：`PreviewRemoveCause` 只返回后果（是否恢复通知、仍有哪些
  其它已确认原因），不改状态；`ConfirmRemoveCause` 确认后只重算受影响主体的
  通知决定，已发出通知保留其当时依据快照（`basis`），不被新解释覆盖；被操作者
  移除的原因不会因重复观察自动复活。
- **重复观察不增加虚假原因**：同一 (子身份, 父源) 只保留一条解释，同轮重复
  告警只并入来源；原因补到走状态升级而非新建。
- **分离持久化**（data 目录下）：
  - rules.json —— 规则集及版本（每个事件记录处理它的规则版本）
  - alerts.json —— 原始告警，逐条原样保存
  - incidents.json —— 事件身份（含开始/结束、合并与抑制的告警来源）
  - suppressions.json —— 抑制关系（含状态与判定规则版本）
  - notifications.json —— 通知本地记录（去重）
  - explanations.json —— 多原因解释（三态、历史变迁、关联范围）
  - decisions.json —— 每主体当前通知决定（抑制轮次与恢复通知判重）
- **通知暂不外发**：notify.Notifier 接口已定义，当前用 Recording 实现只记录事件，
  后续可直接接通知通道。

## 运行内置“多原因关联序列”

```sh
go run ./cmd/alertcorr -data /tmp/alertcorr-data
```

序列覆盖：父故障开火 → 重复告警合并 → 子告警按依赖证据抑制 → 恢复 →
一个告警同时被两个独立原因抑制（交叉关联）→ 一个父恢复不重新通知 →
迟到恢复不得关闭新事件 → 进程重开后多原因状态保持、历史可追溯 →
两个原因先后恢复，最后一条消失才恢复通知且只通知一次 → 待核实原因不压掉独立
告警 → 父告警迟到、证据后补再吸收 → 规则图收窄撤回对应解释 →
预演移除原因（确认前不改状态）、确认后只改变受影响通知决定 →
关联范围收窄与已发通知依据快照可追溯 → 重复重放全部告警不产生多份通知。
结束后逐条核对并输出报告；任何一项失败则以非零码退出。通知只写本地记录不真实发送。
