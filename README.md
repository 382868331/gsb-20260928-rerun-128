# 告警关联运行系统（Go）

把同一故障引起的重复告警归并为一个事件，依据显式服务依赖抑制子告警，
并正确处理恢复、再次发生、迟到恢复与进程重启。通知只录制，不真实发送。

## 设计要点

- **三类身份分别持久化**（`data/` 下三个 JSON 文件，原子写入）：
  - `rules.json`：规则版本历史（当前 `rules-2026-09-29.v1`）。
  - `raw_alerts.json`：原始告警，接收即只追加落盘，不就地修改。
  - `events.json`：关联后的事件身份，含全部合并来源与抑制证据。
- **不凭消息相似合并**：事件指纹 = 服务 + 资源 + 本轮 `StartsAt`
  （见 `internal/model` 的 `Fingerprint`）。同一故障的重复告警并入同一事件；
  消息文本完全不同也不影响去重。
- **抑制必须有明确依赖证据**：仅当规则中存在 `child -> parent` 依赖边，
  且父故障事件在子告警发生时开放，才抑制；证据链（规则版本、依赖路径、
  父事件 ID、理由）随事件持久化。
- **恢复与再次发生**：每个事件记录本轮 `TriggerStartsAt`，恢复只与同轮次
  事件配对。上一轮的迟到恢复在检测到新一轮已触发时被忽略并记入
  `UnmatchedResolves`，不会关闭新一轮事件。
- **重启可复现**：引擎对全部原始告警按故障时间线确定性重放，事件 ID 由指纹
  哈希派生；重启后抑制关系自动恢复，且不会重复发送通知。
- **通知可插拔**：`notify.Sink` 接口当前实现为 `RecordingSink`，只在内存记录
  “本应发出”的开启/恢复/抑制通知；后续接入真实通道只需新增实现。

## 目录

- `internal/model`：原始告警、规则版本、依赖、事件与抑制证据模型。
- `internal/store`：三类数据的 JSON 持久化与加载。
- `internal/engine`：关联引擎（指纹去重、依赖抑制、恢复配对、重放复现）。
- `internal/notify`：通知接口与录制实现（不外发）。
- `internal/scenario`：内置 `web -> api -> db` 依赖故障序列。
- `cmd/alertcorr`：两阶段演示（含中途模拟重启）。

## 运行

```bash
go test ./...          # 逐项核对：开始/结束时间、合并来源、抑制证据、重启、迟到恢复
go run ./cmd/alertcorr -data data   # 端到端演示
```

演示序列：

1. 阶段一：db 根因告警；api、web 子告警沿依赖被抑制；一条文本完全不同的
   db 重复告警按指纹并入；各服务恢复，事件 10:00 开启、10:12 关闭。
2. 模拟进程重启，从磁盘重载规则、原始告警与事件（抑制关系保留，不重发通知）。
3. 阶段二：db 10:20 再次发生，api 再次被抑制；第 1 轮的迟到恢复到达被忽略；
   第 2 轮由自己的恢复在 10:30 关闭。
